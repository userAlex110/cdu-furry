# 优化路线

分级按三件事一起看：收益、成本和验收。收益是少出错、少泄密或少返工。成本是要动的层，以及要不要人、控制台或真实 AppID。验收是怎样证明做完，而不是「看起来合理」。

后端选型是待定决策。这里不比较价格。上游 README 的历史费用句子未对照过账单；CloudBase 国内站的对照还在主协调那边，结果回来之前不写金额。

## 已经在本分支做的

| 项 | 收益 | 成本 | 验收 |
| --- | --- | --- | --- |
| `docs/` 四份接手文档、`AGENTS.md`、`CONTRIBUTING.md` | 下一位 AI 不必重新猜架构 | 只加文档 | 文件存在，且不被 gitignore |
| Issue / PR 模板、`repo-check`、GitHub Actions | 密钥和断链页面能在本地被抓住 | 一个 Node 脚本，无新依赖 | `node scripts/repo-check.mjs` 退出码 0 |
| `sitemap.json` 识猫路径改为 `pages/packageA/pages/recognize/recognize` | 允许收录的规则重新指向真实页面 | 一行配置 | 检查脚本确认该页在 `app.json` |
| `cloudApi.getDate` 返回传入的时间 | 以后传入日期时不再被悄悄换成「现在」 | 一个函数。现有调用都不传参，可见行为不变 | 脚本用 `2020-01-02T03:04:05.000Z` 断言 |

没有改品牌、底栏、依赖大版本和 `functionsEMAS/`。

| `getCatLocations` 只检查登录，不检查 `mapAccess`。`setting` 对登录用户可读，校区中心也在里面 | `getCatLocations.js` 开头；`map.js` 只在页面里调用 `checkCanUseMap`；`policies/miniprogram.yaml` 的 `setting` | 地图权限和接口一致，避免绕过页面拿到坐标 | 改云函数，并核对设置集合的读规则 | 未批准用户调用接口被拒绝；设置里的坐标不对普通用户全部开放。待人工 |

## 待人工，不能在这次标成完成

- 微信开发者工具编译、模拟器点击、真机预览。
- 使用成大自己的 AppID 和管理员扫码。当前配置仍是上游 AppID，没有拿它去预览或上传。
- EMAS 控制台里的集合权限、定时触发器和 `catFace` 是否部署。
- COS 桶的实际地域、权限和账单。
- CloudBase 与 EMAS 的价格对照。
- 打开 GitHub Issues。失败记录见 `docs/development-workflow.md`。

## 建议的下一批顺序

1. 管理员打开 Issues，把流程文档里的两张拟议题补上编号。
2. 产品确认：成大是否沿用「猫谱 + 审核 + 地图」这套范围，地图默认对谁开放。
3. 价格结论写回一份新的 ADR 之后，再开后端选型的实现 Issue。
4. 在那之前，前端只做有检查覆盖的缺陷，后端只追加记录。
